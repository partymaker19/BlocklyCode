# BlocklyCode

Браузерная платформа для обучения программированию через визуальные блоки (Google Blockly). Пользователь собирает программу из блоков, а приложение генерирует из них код на выбранном языке и выполняет его прямо в браузере.

## Возможности

- **4 языка исполнения без бэкенда**: JavaScript (нативно), Python (pyodide/WASM), Lua (fengari), PHP (php-wasm). Сгенерированный код отображается в редакторе Ace.
- **26 обучающих задач** с автопроверкой:
  - 22 базовые: вывод → арифметика → переменные → условия → циклы → списки → вложенные циклы;
  - 4 продвинутые (A1–A4): анализ числа, сумма массива, min/max, частоты символов.
  - Каждая задача оценивается 1–3 звёздами за оптимальность решения, есть пошаговые подсказки (RU/EN), прогресс хранится в localStorage.
- **Кастомные блоки**: вывод текста с цветом (`add_text`), ввод (`py_input`, `py_input_number`), словари (`dict_*` — определены, но по умолчанию скрыты из тулбокса), дата, слайдер, угол, битмап, HSV-цвет.
- **Аккаунты**: регистрация/вход, сохранение рабочих областей на сервере; при недоступности API — автоматический откат на localStorage.
- **Интерфейс**: полная локализация RU/EN, тёмная тема, мобильная версия, поиск по тулбоксу, аннотации поверх рабочей области (Konva), экспорт/импорт проектов (XML/JSON), генерация PDF.

## Запуск

Требуется Node.js 18+.

```bash
# 1. Установить зависимости (корень + app)
npm install

# 2. Запустить бэкенд (порт 4000) и фронт-девсервер (порт 8080) одновременно
npm run dev

# или по отдельности:
npm run server   # только API: http://127.0.0.1:4000
npm start        # только фронт: http://localhost:8080 (проксирует /api на 4000)
```

Продакшен-сборка:

```bash
npm run build    # собирает app/dist/
```

> **Важно (хостинг):** ввод через `input()` использует `SharedArrayBuffer`, поэтому страница должна отдаваться с заголовками **COOP: same-origin** и **COEP: require-corp** (crossOriginIsolated). Для Apache в `dist/` копируется готовый `.htaccess`; для Nginx/др. задайте заголовки в конфиге.

## Структура проекта

```
├── app/            # фронтенд-приложение
│   ├── src/
│   │   ├── index.ts        # точка входа: инициализация Blockly, редактора, аннотаций
│   │   ├── index.html      # разметка + стили
│   │   ├── tasks.ts        # реестр задач: описания, подсказки, валидаторы
│   │   ├── toolbox.ts      # конфигурация тулбокса (категории блоков)
│   │   ├── codeExecution.ts# генерация и запуск кода
│   │   ├── sandboxWorker.ts# воркер-песочница (JS/Python/Lua/PHP, ввод)
│   │   ├── generators/     # генераторы кода кастомных блоков (js/python/lua/php)
│   │   ├── blocks/         # определения кастомных блоков
│   │   ├── ui/             # модули интерфейса (тема, модалки, контекстное меню, мобильная версия)
│   │   └── localization.ts # RU/EN строки интерфейса
│   ├── tests/              # Vitest-тесты (валидаторы задач)
│   └── webpack.config.js
├── server/index.js         # Express API: аутентификация (dev-стаб), хранение workspace
├── solutions/              # эталонные решения задач в XML (импортируются в рабочее поле)
└── scripts/                # вспомогательные скрипты (генерация PDF)
```

## Тесты и качество кода

```bash
npm test           # все тесты (vitest, из app/)
npm run lint       # ESLint (0 ошибок обязателен, предупреждения допустимы)
npm run typecheck  # tsc --noEmit
cd app && npm run format   # Prettier (переписать файлы)
```

CI (`.github/workflows/ci.yml`) на каждый push/PR в main гоняет: install → typecheck → lint → tests → build.

Тесты проверяют валидаторы задач: общий раннер `tests/all_tasks.test.ts` прогоняет все 26 задач (валидатор обязан принимать корректный вывод — защита от регрессий вида «задача непроходима»), плюс e2e-решения со звёздами для mult_table и char_freq: рабочая область собирается из JSON/XML → генерируется JS → выполняется → проверяется результат и количество звёзд.

## Добавление новой задачи

1. Добавьте id в тип `TaskId` в `app/src/tasks.ts`.
2. Опишите задачу: `title`, `description`, `hint` (RU/EN) и функцию `validate(ws, outputLines, lang)` → `{ ok, stars }`.
3. Внесите id в `TASKS_ORDER_BY_DIFFICULTY` (basic/advanced).
4. Добавьте тест валидатора в `app/tests/` и (опционально) эталонное решение в `solutions/`.

## Статус и ограничения

- Аутентификация и хранение workspace на сервере — **dev-стабы** (любой email, данные в памяти процесса); перед продакшеном нужна настоящая БД и проверка паролей.
- Прогресс задач хранится только в localStorage браузера.
